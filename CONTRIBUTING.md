# Contributing

Thanks for helping make this prototype more useful, trustworthy, and accessible. New contributors are welcome—small fixes, documentation, research, design feedback, and tests all help.

## Start here

1. Read the project scope and safety boundaries in [README.md](./README.md).
2. Open an issue describing the change, or pick an existing issue. For a major feature, discuss the approach before starting.
3. Fork the repository, create a focused branch, and keep changes small enough to review.
4. Run the checks before opening a pull request:

   ```sh
   npm test
   npm run build
   ```

5. Explain what changed, how you tested it, and what remains unverified in your pull request.

## Safety and privacy

- Use synthetic or public-domain examples only. Never submit real people's complaints, personal information, precise locations, private correspondence, credentials, or confidential datasets.
- Do not present prototype content or generated text as an official response, legal advice, verified fact, representative public opinion, or government action.
- Keep AI suggestions transparent, cite authoritative sources when available, and allow uncertainty or abstention. Consequential workflows need human review.
- Do not add provider keys, model artifacts, or unreviewed user-data collection.
- Report security concerns privately to the repository maintainers rather than publishing exploit details in a public issue.

## Pull requests

- Match the existing React, TypeScript, and Node.js patterns.
- Add or update tests for changed behavior.
- Include accessibility and mobile considerations for interface changes.
- Avoid unrelated refactors and new dependencies unless the change requires them.

By contributing, you agree that your contributions are provided under the repository's Apache-2.0 license.
